# ИИ-консультант Store — хакатон ИИкузница

Агент поддержки для store.softline.ru: подбирает ПО по каталогу Store, сверяет лицензии,
отвечает по базе знаний, готовит КП и передаёт сложные случаи менеджеру.

```
support-assistant/
├── Dockerfile          ← единый образ: бэкенд + собранный фронтенд (его собирает Railway)
├── docker-compose.yml  ← запуск локально, режим разработки, пересборка каталога
├── railway.json        ← настройки деплоя на Railway
├── backend/            ← сервер: Node 20 + Fastify, REST + WebSocket, хранение в JSON-файле
├── frontend/           ← React-приложение; логика агента — frontend/src/api/core + mock/
└── data/               ← скрипты: каталог из фида, выжимка из переписок
```

Логика агента (поиск по фиду, расчёт цен, подбор, КП) — общий код из `frontend/src/api`.
Сервер вшивает его в свой бандл, поэтому агент на сервере и в офлайн-режиме ведёт себя одинаково.

## Запуск в Docker

```bash
docker compose up --build
```

- http://localhost:8080 — витрина Store с виджетом консультанта
- http://localhost:8080/operator — кабинет менеджера (обращения, КП, аналитика)
- http://localhost:8080/chat — чат на весь экран

Обращения и КП хранятся в томе `app_data` и переживают перезапуск.
Остановить: `docker compose down` (данные останутся), начать с чистого листа: `docker compose down -v`.

### Режим разработки

```bash
docker compose --profile dev up
```

http://localhost:5173 — правки во `frontend/src` и `backend/src` применяются сразу (бэкенд на :8000).

### Пересобрать каталог из нового фида

Положите `Mindbox.yml.gz.xml` и папку `чаты поддержки` сюда, затем:

```bash
docker compose --profile tools run --rm catalog
docker compose up --build app
```

## Деплой на Railway (автодеплой из `main`)

1. Запушьте проект на GitHub. Удобнее всего, чтобы содержимое `support-assistant/` было корнем репозитория.
   Исходный фид (290 МБ) и PDF в репозиторий не нужны — они в `.gitignore`.
2. На railway.com: **New Project → Deploy from GitHub repo** → выберите репозиторий.
   Railway найдёт `railway.json` и соберёт `Dockerfile`.
   - Если проект лежит в подпапке репозитория — в настройках сервиса укажите **Root Directory** = эта подпапка.
   - Ветка для автодеплоя — `main` (Settings → Source).
3. **Том для данных:** в сервисе → **Volumes → New Volume**, путь монтирования `/data`.
   Без тома обращения и КП сбрасываются к демо-данным при каждом деплое.
4. **Публичный адрес:** Settings → Networking → **Generate Domain**. Порт сервер берёт из переменной `PORT`,
   которую выставляет Railway, — ничего настраивать не нужно.
5. Готово: каждый пуш в `main` пересобирает и перезапускает сервис. Проверка здоровья — `/healthz`.

Перед показом откройте сайт заранее: первая сборка занимает 2–3 минуты.

### Переменные окружения

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `PORT` | `8080` | порт сервера (Railway задаёт сам) |
| `DATA_DIR` | `/data` | где хранить обращения и КП |
| `ALLOW_RESET` | `true` | кнопка «Сбросить демо-данные» в кабинете; `false` — выключить на публичном демо |
| `LOG_REQUESTS` | `false` | писать в лог каждый HTTP-запрос |
| `VITE_USE_MOCK` | `false` | build-аргумент: `true` — собрать фронтенд с офлайн-заглушкой вместо бэкенда |
| `APP_PORT` / `DEV_PORT` | `8080` / `5173` | порты в docker compose |

## Без Docker

```bash
cd backend && npm install && npm run dev      # API на :8000
cd frontend && npm install && npm run dev     # http://localhost:5173, /api → :8000
```

Фронтенд без бэкенда (всё в браузере): `VITE_USE_MOCK=true npm run dev`.
Статическая сборка с заглушкой для хостингов без Node — `frontend/Dockerfile` (nginx).

## Ограничения демо

- Агент работает на правилах поверх каталога, без языковой модели. Модель подключается в `frontend/src/api/mock/bot.ts`
  (функция `generateReply`), интерфейс и сервер менять не нужно.
- Нет авторизации: кабинет менеджера открыт всем, у кого есть ссылка. Для публичного демо можно выключить сброс (`ALLOW_RESET=false`).
- Хранилище — один JSON-файл, рассчитано на демо-нагрузку и один экземпляр сервера.

Подробнее о фронтенде, данных и контракте API — в [frontend/README.md](frontend/README.md).
